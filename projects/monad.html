monad

One daemon for agentic coding and PR review. Sessions run any coding agent over the Agent Client Protocol, outlive the client that started them, and can be attached from the CLI, an editor, or a phone.

TypeScript Bun ACP Claude Agent SDK Codex GitHub App SQLite

Overview

monad replaces two earlier projects, Forge (an agent orchestration platform) and LastGate (a pre-flight guardian for AI-generated code), with a single engine. A session is a working directory, an agent backend, and a playbook. Interactive sessions are opened by a person; review sessions are opened by a GitHub pull request, run diff-scoped checks, and post results back. Both are the same kind of session, so fixing a failing review means attaching to it, not launching a different tool.

Key Features

  • Speaks the Agent Client Protocol on both sides: an ACP client toward Claude Code, Codex, and Gemini CLI; an ACP agent toward its own clients and any ACP-capable editor
  • Sessions persist as an append-only event log in SQLite and survive client disconnects; attaching is a replay plus a live subscription
  • Vendor auth stays inside the vendor binaries; monad never holds an API token for subscription-backed agents
  • Type check, lint, test, secret scan, and build run as session tools shared by interactive and review modes
  • Local-first and MIT: loopback only, zero telemetry, no cloud dependency

Architecture

A Bun and TypeScript monorepo. The daemon owns sessions, the event log, and a permission policy that answers agent requests automatically in review mode and forwards them to a person in interactive mode. The CLI, a stdio bridge for editors, and later desktop and mobile clients are thin ACP clients over one HTTP transport. Check and GitHub App code is carried forward from LastGate; the provider-neutral agent loop and its test suite from Forge are the engine spec.
